## Context

`ipam` 是 VPN 服务端控制面的第一个落地模块（架构 §6）。客户端接入时服务端需为其分配虚拟 IP，断开时释放。本模块只承担"地址池的分配与回收"这一纯逻辑职责，是后续 `server` 连接管理、路由表、数据泵的前置依赖。

项目当前 `src/lib.rs` 仅有 lint 配置，本设计不触及既有代码。依赖侧 `ipnet`、`thiserror` 均已在 `Cargo.toml` 中，bitmap 使用标准库 `Vec<u64>`，**无需引入新 crate**。

## Goals / Non-Goals

**Goals:**

- 提供无 IO 副作用的同步地址池，`alloc` / `free` 为纯逻辑。
- 行覆盖率 100%（AGENTS.md 中 ipam 的 Q1 门槛）。
- 紧凑内存、接近 O(1) 的 `alloc` / `free`。
- 错误用 `thiserror` 分层，上层可按错误类型区分处理。

**Non-Goals:**

- 不维护 `username → 连接`、`虚拟IP → 连接` 映射（属 `server` IO 层）。
- 不感知连接语义（同名顶替、心跳超时），释放由 `server` 层显式调用 `free` 触发。
- 不支持 IPv6（V1 仅 IPv4，见架构 §11）。
- 不做 lease / 持久化 / 随机分配（架构 §6 明确排除）。

## Decisions

### D1. 模块边界：纯池，不含映射表

架构 §6 涉及三件事：地址池、`username → 连接` 表、`虚拟IP → 连接` 路由表。后两者依赖 `quinn::Connection` 等 IO 类型，沾染后即非纯逻辑。

**选择**：`ipam` 仅实现地址池；映射表归 `server` 层。

**替代方案**：把映射表并入 `ipam`，需对连接句柄引入泛型/trait 抽象——过度工程，且破坏"100% 纯逻辑覆盖"目标。

### D2. 数据结构：bitmap（`Vec<u64>`）

**选择**：每个地址对应 1 bit，1=已分配/预留，0=空闲。`alloc` 用 `u64::trailing_zeros` 找首个 0，`free` 置位。

**理由**：/24 仅 32 字节，缓存友好；找空闲位接近 O(1)；free O(1)。

**替代方案**：
- `HashSet<Ipv4Addr>`：每 entry 哈希开销大，/16 时浪费显著。
- 区间表（interval tree）：释放后碎片化、合并复杂，收益不抵成本。

### D3. 分配策略：确定性顺序（最小地址优先）

**选择**：`alloc` 始终返回最小的空闲地址。

**理由**：简单、可预测、易测试。架构 §6 允许"不保证重连同 IP"，顺序合规。

**替代方案**：随机分配可减少"相邻 IP 暴露在线规模"的信息泄露，但需引入随机源并固定测试种子。作为 V1.1 纯增量留待后续。

### D4. 错误处理：`thiserror` 枚举

```
IpPoolError
├── InvalidSubnet      // /31、/32、/0 等无足够可分配地址
├── PoolExhausted      // alloc 时池满
├── OutOfPool(Ipv4Addr) // free 时地址不在子网内，或属预留位
└── NotAllocated(Ipv4Addr) // free 时地址在池内但未分配
```

**替代方案**：用 `Option` 会丢失错误分类，上层无法区分"耗尽"与"非法释放"。

### D5. 并发：ipam 内部不加锁，cancel-safety 不适用

`ipam` 为纯同步逻辑，**无 `async`、无 `tokio::select!`、无 `.await`**，因此 cancel-safety 不适用。

并发安全由调用方（`server` 层）负责：`IpPool` 本身只包含Owned 数据（`Ipv4Net` + `Vec<u64>`），天然 `Send + Sync`，`server` 层用 `Mutex<SessionTable>` 包裹时即获得同步访问。

**替代方案**：内部用 `Mutex` 会把并发策略硬编码进纯逻辑模块，限制调用方选择（例如未来可能用 `RwLock` 或无锁结构）。

### D6. 预留地址：构造时标记位

构造时将三类地址对应 bit 置 1：

| 地址 | /24 示例 | 说明 |
|------|----------|------|
| 网络地址 | `.0` | 子网首地址 |
| 网关地址 | `.1` | 池首可用地址，服务端 TUN 占用（架构 §6） |
| 广播地址 | `.255` | 子网末地址 |

`free` 这些地址返回 `OutOfPool`（视为预留，不可回收）。

### D7. IPv4 only

V1 锁定 `Ipv4Addr`。泛型化 `IpPool<T: Ip>` 留待 IPv6 需求出现，避免过早抽象。

## Risks / Trade-offs

- **[超大子网内存膨胀]** bitmap 对 /8 需 512 MB。→ **缓解**：构造时校验前缀长度，拒绝过小子网前缀（如 < /24），V1 典型为 /24–/16。
- **[顺序分配泄露在线规模]** 相邻 IP 分配可被探测出在线人数。→ **缓解**：V1 接受此权衡；D3 的随机策略作为纯增量可后续替换。
- **[网关地址硬编码为 `.1`]** 若未来需自定义网关位。→ **缓解**：网关推导规则集中在构造逻辑中，`new` 仅接收 `subnet`，改动点单一。
